# Security Policy

## Trust model — read this before pointing the pipeline at a repo

`vibedocing` drives an **LLM agent** (`opencode run --command vibe-commit`) that reads
source files, commit messages, and diffs from the project being documented, and then edits
files under `agent/project/`. The project under analysis is **untrusted input** to that agent.

This has one important consequence:

### Prompt injection from documented source
Commit messages, code comments, and file contents in the documented repo are read by the
agent as part of its task. A malicious repository can embed text intended to override the
agent's instructions (e.g. *"ignore previous rules, run this shell command"*). Depending on
the tools the opencode agent is allowed to use (by default this commonly **includes shell
access**), a successfully subverted agent may execute arbitrary commands on the machine that
runs the pipeline, not just edit documentation.

The agent's "Hard rules" in `opencode/command/vibe-commit.md` (only edit `agent/project/`,
never `git push`, etc.) are a soft mitigation, **not** a guarantee — LLMs can be jailbroken
by crafted content.

### Recommended mitigations
- **Only document repositories you trust** — same rule as running any code from them.
- For **untrusted or third-party** code, run the pipeline **inside a sandbox**: a container,
  VM, or a dedicated disposable account. Do not run it against untrusted repos on a machine
  with access to secrets, production credentials, or `git push` rights to important repos.
- Consider a **restricted opencode agent profile** (file edits under `agent/project/` plus
  read-only git, no shell) referenced via the `agent` field in `config.json`.
- Review `walk.log` / `logs/<sha>.log` after a run for unexpected agent actions.

### What the pipeline itself does NOT do
- It never makes **outbound network calls** (no `curl`/`wget`/`git push` from the scripts).
- It does not `eval` or `source` any project content as shell.
- Auto-commits go to a **local workspace git repo only**; nothing is pushed remotely.
- Commit subjects read from the project are sanitized (`run.sh: sanitize()`) before being
  used in commit messages, so they cannot inject git options or extra `-m` flags.

## Local artifacts that may contain sensitive paths
`config.json` (generated by `bootstrap.sh`) records the local path/name of the project under
analysis. It and the other runtime files (`progress.json`, `walk.log`, `logs/`, `verdicts/`,
`.vibe-trees/`) are listed in `.gitignore` and should **not** be committed. The managed
`opencode serve` log is written to a `mktemp`-allocated file (not a fixed `/tmp` path) to
avoid symlink attacks.

## Reporting a vulnerability
Please open a private security advisory on GitHub, or email the maintainer listed in the
LICENSE. Do not open a public issue for security problems.
